# 已知弯路与规避（2026-09 实测）

## 1. Zotero 来源

- 桥接脚本 `get <KEY>` 可能返回子笔记而非论文条目（本地 API 会连同 children 返回）。用 `search` 确认条目类型为 `journalArticle`，必要时直接查本地 API `itemKey=<KEY>`，再从 attachments 拿 PDF 绝对路径。

## 2. 论文原图提取（核心易错点）

- IEEEXplore 导出的 PDF 中，插图大多是**内嵌栅格**：用 `pdfplumber` 的 `page.images` 可直接拿到精确 bbox（x0, top, x1, bottom，单位 pt）。
- 裁剪流程：`pdftoppm -png -r 300` 渲染对应页 → `PIL` 按 `bbox × (300/72)` 裁剪 → OCR 核验。
- **裁切陷阱**：图注相邻的表格如果也是栅格（实测 Table IV/V 以栅格嵌入页面），跨区域合并裁剪会把表格裁进"图"里。只裁图注正上方的单个图片 bbox，不做 union；OCR 应含图内轴标/图例文字，不应出现表头文字。
- 同页多图时不要用 dict 存（键会覆盖），用 `[(page, name, bbox), ...]` 列表。
- 图中无文字不等于失败：先检查像素统计（非白像素占比）再决定是否重裁。

## 3. MinerU / 正文转换（备用路径）

- 轻量接口返回体包一层 `data`：需 `r = r.get("data", r)`。
- OSS 预签名上传 URL 拒绝带 `Content-Type` 的 PUT（urllib 传 bytes 会自动附加导致 403 SignatureDoesNotMatch）→ 用 `http.client` 裸 PUT。
- `obsidian-paper-reading` 的脚本已内置上述修复；若转换仍失败，直接退回本地 PDF 抽取。

## 4. 文件写入与脚本

- `apply_patch` 的 Add File 每行必须以 `+` 开头；内容行若本身以 `-` 开头（Markdown 列表）要写成 `+-`，否则补丁校验失败。
- 先写标题与整句文案、再写 SVG，避免内容返工连带坐标重排。

## 5. SVG/XML 语言与引号

- `font-family` 属性统一：外层单引号 + 字体名双引号：`font-family='"Microsoft YaHei", "PingFang SC", Arial, sans-serif'`。
- 混用引号（如 `'"Microsoft YaHei", "PingFang SC', ...`）会 XML 非法，`svg_quality_checker` 报 `not well-formed`。
- 文本用原始 Unicode（—、→、θ、ᵀ）；XML 保留字符必须转义（`&lt;`、`&amp;`）；禁止 HTML 实体与 `rgba()`。
- 同族数字/复杂度文本可用 `Consolas, Courier New, monospace` 栈，但引号约定同上。

## 6. 质检

- `svg_quality_checker.py`：任何 error 必须先修复再 `finalize_svg.py`；图片显示尺寸大于源尺寸会报模糊 warning。
- `formula_audit.py`：mixed 策略下简单行内符号属合法文本，用 `--warn-only` 放行并在 `design_spec.md` 注明策略；复杂公式必须为 PNG。
- 本会话若不支持图像输入：用「图注 + 正文 + OCR」交叉核验，不在页面上臆造曲线/形状细节。

## 7. 环境

- 运行时 Python：`C:\Users\ASUS\.cache\codex-runtimes\codex-primary-runtime\dependencies\python\python.exe`；Poppler 同目录 `native\poppler\Library\bin`（有 pdfinfo/pdftoppm，无 pdftotext，用 pdfplumber/pypdf 抽文字）。
- 无 flask → 跳过 live preview（不影响导出）；无 LibreOffice → 跳过 soffice 视觉冒烟，改用 checker + 内容抽检，交付时提示用户打开核对。
- 控制台中文乱码：命令前设置 `$env:PYTHONIOENCODING="utf-8"`。

## 8. 权限与清理

- 写 vault / D 盘 / 技能目录都先 `request_permissions`；Windows 沙箱可能拦截 `Remove-Item -Recurse`，改用 Python `os.remove` / `os.rmdir`（显式字面路径，先 `GetFullPath` 校验在目标范围内）。
- 每阶段清理：渲染 PNG、traineddata、backup/svg_final/旧导出、pycache、OCR 输出；保留 `svg_output/ images/ notes/ design_spec.md spec_lock.md`。

## 9. 语言返工教训

- 标题/要点一旦口语化，后期批量改写成本高且易漏。正确顺序：文案按学术语域定稿 → 设计 → 生成 → 只做局部微调。替换表见 deck-language-register.md。

## 10. 封面版式（连续两次返工的默认规则）

- 症状：封面左上角出现竖向装饰条（如 `rect x=60 y=52 width=6 height=46`），主标题 y≈300+ 造成大片顶部留白，整体偏"下坠"。
- 默认规则（1280×720）：
  - 封面不使用左上竖向条、不用大面积顶部装饰；背景装饰宜放在右下/右上并克制；
  - 主标题基线置于 y ≈ 200–260，副题紧跟（间距 50–60px），作者/研究所/日期再下移 90–130px，底部放来源行；
  - 顶部到主标题的留白不超过画布高度的约 30%。
- 生成后自检：封面是否仍有竖条或"标题沉底"观感；每次交付前对照本规则。

## 11. 沙箱授权写入失败（目录所有权问题，2026-09 实测）

- **症状**：`request_permissions` 授权写 vault / 技能目录后，`exec_command` 报
  `helper_unknown_error: setup refresh had errors`，且 `apply_patch` 一并失效，需重启应用；
- **根因**：沙箱授权需以登录账户向目标目录写入 ACE；若目录所有者是沙箱账户
  （`CodexSandboxOffline`，由沙箱进程创建文件/目录造成）或 SYSTEM（如盘符根目录），
  `SetNamedSecurityInfoW` 返回 5，刷新失败 → 助手崩溃；
- **日志**：`~/.codex/.sandbox/sandbox.<date>.log` 搜索 `write ACE failed` 与 `SetNamedSecurityInfoW failed: 5`；
- **判据**：`(Get-Acl "<dir>").Owner` 为登录用户才可授权；对照 `D:\组会报告`（ASUS，正常）与 `D:\`（SYSTEM，必失败）；
- **修复**（管理员 PowerShell）：
  `takeown /f "<dir>" /r /d y` → `icacls "<dir>" /grant "ASUS:(OI)(CI)F" /t /c` → `icacls "<dir>" /setowner "ASUS" /t /c`，
  之后重启应用并重试写入（实测修复后「授权→写入→清理」全程正常）；
- **预防**：① 避免由沙箱身份创建输出目录（新建目录尽量由用户账户完成）；② 写盘前检查 Owner；
  ③ 不要申请盘符根目录作为可写根；④ 兜底方案用纯 ASCII 的 ps1/cmd 脚本交给用户双击执行。

## 12. 演讲稿（口播稿）生成（2026-09 实测）

- **先定时长与结构，再动笔**：时长、内容重心、输出目录必须在生成前与用户确认，或先给出默认方案再落笔。
  实测教训：先按 20 分钟写完整稿，再被要求压到 10 分钟并以方案/算法为重点，等于整篇重写。
- **默认基线**：组会讲稿默认 10 分钟，正文 2200-2400 字（按 230 字/分钟朗读）；配套 PPT 26 页时只精讲
  10-14 页，背景知识页降级为「备用材料」，不占主时间轴。
- **内容重心**：方案（机构/系统设计）与建模算法（几何映射 → 运动学 → 静力学 → 刚度合成）合计约 6 分钟；
  数据只保留支撑结论的 3-5 组；论文不含学习类算法时不要硬套「算法」章节，改为讲解析建模链与迭代逆解。
- **格式**：用 `【PXX｜标签】` 标注页码便于对照放映；正文口语化但表述克制；文末各给一条「超时删什么 / 欠时补什么」。
- **交付**：Markdown 与 DOCX 双版本，默认目录 `D:\组会演讲稿\`，文件名 `主题_组会演讲稿_姓名_时长.docx`；
  该目录若不存在需先 `request_permissions` 再新建（D 盘根目录 Owner 为 SYSTEM，不可直接申请根目录写入）。
- **自检**：统计可朗读字数（排除标题、表格与标记行）换算分钟数，落在目标 ±0.5 分钟内再交付；
  同时核对页内关键数字与论文原文一致。


## 13. 论文原图被压小 / 框架页用流程图（2026-09-16 实测）

- **症状**：分模块页把两张论文原图塞进固定的 460×178 扁框，`xMidYMid meet` 按高度缩放后，
  竖长图（如 814×930）只显示成 155×178，投影时完全看不清；用户连续指出 15/16/20/21 页。
- **根因**：图框尺寸是按版面先定死的，而不是按图片原始宽高比反算；扁框 + 竖图 = 大面积 letterbox。
- **规则**：先取图片原始宽高比（`analyze_images.py` 或 PIL），再按 `references/image-layout-spec.md` 反算显示尺寸，
  **图框必须贴着图片尺寸画**（图框 = 图片 + 12px 内边距），不要先画固定框再往里塞图。
- **证据页推荐骨架**（1280×720）：图区 y=154–478，左右各一栏（栏宽 560、栏心 x=340 / x=940），
  两栏图框底边对齐、图注统一下压到 y≈504，y=522 加 hairline，下方 y=548 起排三栏要点（x=60/460/860，宽 360，14px，行距 22）。
  实测显示面积比旧版放大 2.3–2.9 倍。
- **框架/大纲页不要用方框 + 箭头流程图**：用户明确认为「单薄、不大气」。默认改为 2×3 模块卡片：
  卡片 360×212、行距 20、顶部 4px 强调条，卡内为大号编号（30px）+ 模块名（19px）+ 两行说明（14px）+ 页码区间（13px）。
- **背景/信息页填补空白**：背景页用「左文右图」（正文栏压到约 620px，右侧放论文图 1 场景图）；
  信息页用「大卡 + 三栏」（大卡放中文题目与逐位作者单位，三栏放出版信息 / 作者与单位 / 研究领域与关键词），不要留半页空白。
- **作者信息要详实**：逐位作者写中文单位，单位取自论文首页脚注（pdfplumber 抽 words，按 top/x0 过滤页脚区），
  并标注通讯作者；只写英文姓名列表会被判为不详细。
- **本机已确认可用的原图提取链**：`pdfplumber` 读 `page.images[].bbox` → poppler `pdftoppm.exe -png -r 300` 渲染该页 →
  PIL 按 `bbox × (300/72)` 裁剪（外扩 6px）→ 用非白像素占比（正常图形约 0.2–0.3）确认不是空白；
  图号用「图注在图片下方」的 words 区间反查（如 top ∈ [bbox_bottom, bbox_bottom+30]）。
- 新增图片后必须同步补 `spec_lock.md` 的 `## images` 段，否则 `svg_quality_checker.py` 报 spec_lock drift。


## 14. 逐页返工 → 全片统一版式系统（2026-09-16 实测）

**触发信号**：用户连续反馈「这个图也小」「文字和图片重叠」「空白太大」「不要单独，整合所有页排版」。
根因是逐页各写一套骨架，页与页之间列宽、图框、图注基线都不一致，改一处就要再改一片。

- **先定版式系统，再逐页落位**。1280×720 的统一约定（可直接复用）：
  - 页眉：模块标签 `rect(60,44,130,30) rx4 #EAF0F7` + 14px/700 文案；标题 x=60 y=112（32px/800，长标题 31px）；分隔线 y=132（60→1220）。
  - 内容区：y=150–660；页脚：来源 x=60 y=694、页码 x=1220 右对齐，均 13px `#8B95A3`。
  - 网格：通栏 1160（x=60）；双栏 560+40+560（x=60/660）；三栏 360+40+360+40+360（x=60/460/860）。
  - 文字角色：栏头/小标题 14px/700 `#0E5FA8`；正文 14–15px `#1D2733`；注释/图注 13px `#8B95A3`。
- **四种页面骨架**（按图数选一，不要每页自创）：
  - L1 双图证据页：图框底边 y=500，图片 ≤536×326，图注 y=538，hairline y=558，三栏要点栏头 y=582 + 正文 606/626/646（排满 4 行提高信息密度）。
  - L2 通栏图页：图框 (60,150,1160,336)，图注 512，hairline 532，三栏要点 558/584/606/628。
  - L3 左右分栏页：左栏 x=60 w=560、右栏 x=660 w=560；图按比例最大化；栏底再补一条 callout 填满剩余空白。
  - L4 纯文本页：面板直接落在双栏/三栏网格上（560 或 360 宽），底部用 `1160×56~96` 结论条收尾。
- **图框规则**（消除「框大图小」的根因）：图框尺寸 = 图片显示尺寸 + 四周 12px，水平居中于栏心（左栏 340 / 右栏 940）；
  绝不先画固定框再往里塞图。图注固定在框下 26px，13px 居中。
- **论文原图必须按原始分辨率重提**（用户授权「必要的话修改原论文版式」时更应如此）：
  IEEE 导出 PDF 的插图为 FlateDecode 原始位图或 DCTDecode JPEG，两种都能直接取原始像素：
  `pdfplumber.page.images[i]["stream"]` → 先 `Image.open(BytesIO(st.get_data()))`（JPEG 分支），
  失败再 `Image.frombytes(mode,(W,H),data)`（Flate 分支，W/H 取 `stream.attrs["Width"/"Height"]`，
  mode 由 `ColorSpace` 的 ICCBased `N` 决定：1=L/3=RGB/4=CMYK）。实测可拿到 1400–2000 px 的原生图，
  比按 300 dpi 渲染页面再裁剪更清晰。图号用「图注在图片下方」的 words 区间反查确认。
- **导出前把源图缩到显示尺寸的约 3 倍**（`Image.LANCZOS` + `optimize=True`）：既避开 checker 的
  "consider downsizing" 警告（阈值是源图 > 显示尺寸 4 倍且两维都超），又把 PPTX 体积压回可接受范围。
- **文本页统一用坐标归一化**（面板 x/w、右栏文字 x 落回网格），比整页重写更快更不易错；
  归一化脚本只改几何、不动文案，等同于 skill 自带的 `update_spec.py` 思路。
- **交付前跑两遍自检**：`svg_quality_checker.py`（0 error / 0 warning）+ 自写「文字框 vs 图片框」几何重叠检测
  （文本宽度按 CJK=字号、拉丁≈0.55×字号估算），避免再次出现文字压图。


## 15. 页面内容 vs 演讲备注、用户改稿后的续改（2026-09-16 实测）

### 15.1 "扩展 PPT 内容"要先分清是页面还是备注

用户说"在 PPT 里扩展我要说的内容 / 丰富修改 PPT 内容 / 我需要脱稿讲"时，有三种互不相同的意图：

1. **改页面文字**——把逻辑、理由、结论写进幻灯片本体；
2. **加演讲者备注**——页面不动，只在 notes 里写口播要点；
3. 两者都要。

实测教训：先按 ② 做了 26 页备注并交付，用户回复"我的意思是丰富修改 PPT 内容"，整轮返工。
**规则：动笔前用一句话确认（"是要改页面上的文字，还是加在备注里？"），或直接两种都做。**

### 15.2 用户手工改过 PPT 后，必须以他的文件为基线

用户会在导出的 PPTX 上直接改字。续改流程固定为四步：

1. **先 diff，再动手**：用 python-pptx 递归（含 GROUP）抓每页文本，与自己的上一版导出逐页做集合差，
   打印 `[only in A] / [only in B]`。实测两次都是 1–4 处文字改动，diff 秒级定位。
2. **回写工程源**：把用户的措辞（含他改的标点与断行）原样写回对应 SVG，不要"顺手润色"。
3. **重新导出**：checker → finalize → svg_to_pptx。
4. **导出后再 diff 一次，确认 0 差异**——这是"没有覆盖用户编辑"的唯一硬证据。

如果用户改动很多且不想回到 SVG 管线，也可直接用 python-pptx 在他的文件上做增量修改（见 15.4）。

### 15.3 两类页面的固定骨架（用户明确要求）

- **实验 / 结果页 → "三段式"**（用户原话："讲清楚别人是如何设计的实验、为什么这么设计、取得什么效果即可，不需要浪费时间"）：
  - ① 实验设计：对象、条件、自变量与因变量、评价指标；
  - ② 为什么这样设计：要验证的命题、为什么取这组变量/条件、与上一页的衔接；
  - ③ 结果与效果：只放结论级数据 + 一句话结论；细节（型号、参数表）不进页面。
- **建模 / 算法页 → "逻辑页"**（用户原话："按照理解讲清楚逻辑"）：
  - ① 为什么要做（问题 → 物理量 → 为什么必须建模）；
  - ② 怎么做（分层递进，逐层标注输入/输出/作用，例如 运动学 → 静力学 → 刚度合成，
    并写明"没有这一步就谈不上……"这类依赖关系）；
  - ③ 结论与适用边界（结论从哪来 + 适用条件/易误读点）。
  - 关键：**不要写成并列要点列表**，要让页面本身呈现因果链。
- 骨架几何（1280×720，可与统一版式系统并存）：图区 y=150–440（图高 ≤266，图宽 ≤536），
  图注 y=466，hairline y=490，三段文字块 x=60/460/860（宽 360），块头 y=516（15px/800/#0E5FA8），
  正文 542/564/586/608/630（14px/22px 行距，每块最多 5 行）。

### 15.4 备注的写、查、删

- **写**（原生路径）：`notes/total.md`，格式为 `# <svg_stem>` 一级标题 + 正文段落；
  再跑 `total_md_split.py <project>` 生成 `notes/<svg_stem>.md`；`svg_to_pptx.py` 会自动嵌入备注。
- **查**：python-pptx 遍历 `slide.has_notes_slide` 与 `notes_slide.notes_text_frame.text`，
  统计"缺备注的页码"，要求为空。
- **删**（用户改稿后要求去掉备注时，保留他的页面编辑）：在原 PPTX 上逐个 `slide.part.drop_rel(rId)`
  删掉 notesSlide 关系再另存；**不要**用"清空文本"作为首选（会留下空的备注页零件），
  drop 失败时才退化为清空文本。实测 26 页 drop 全部成功，导出后 `notes in B: 0` 且页面文本 0 差异。
- 删完顺手把 `notes/<svg_stem>.md` 全部分页文件删掉（保留 `notes/total.md` 作存档），
  否则下次重新导出会把备注又带回来。

### 15.5 版本与代价
